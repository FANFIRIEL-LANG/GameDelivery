# GameDelivery — критерии готовности приложения

**Дата:** 2026-10-27  
**Рабочая ветка:** `feature/asf-bulk-account-import`  
**Базовый коммит:** `5f52ebb45abf853769d972a9760b14d3760fd546`

## Цель

Довести существующий GameDelivery до надёжного Windows-приложения для локальной обработки заказов игровых предметов: импорт заказов Playerok, управление локальным ArchiSteamFarm (ASF), выбор ботов и конкретных предметов инвентаря, резервация активов, настройка прокси и контролируемая отправка Steam-предложения после проверки и явного подтверждения оператора.

## Границы

- Продолжать существующий Python/PySide6 проект; не переписывать приложение с нуля.
- Не сливать feature-ветку в `main` без отдельного согласования.
- Playerok остаётся read-only по продажам: без покупок, вывода денег, смены статуса заказа, создания/редактирования товара или отправки сообщений.
- Все Steam-операции выполнять через локальный ASF. Не использовать прямые Steam Web API для аккаунтов/инвентаря/торгов.
- Не принимать входящие обмены автоматически. Для исходящего предложения обязательны повторная проверка живого инвентаря, точный список активов и ручное подтверждение.
- Не повторять автоматически отправку при неизвестном результате; сначала оператор проверяет исходящие предложения Steam.
- Секреты не коммитить и не писать в логи. Сохранять пароли только в системном хранилище или в предусмотренном временном одноразовом хранилище с ограниченными ACL.
- Поддерживать Windows 10/11 x64 как целевую платформу; Python 3.11+ для запуска из исходников, PySide6 и keyring — существующие зависимости.
- Проверять совместимость ASF-плагина с конкретной версией ASF; CI не считается доказательством реального успешного обмена.

## Подходы

1. **Стабилизировать существующие модули по этапам (выбранный подход).** Сохраняет текущие UI, БД, тесты и разнесение на интеграции; каждый этап имеет критерии проверки.
2. Переписать приложение заново. Отклонено: теряются уже написанные функции и поведение, растёт риск регрессий.
3. Слить текущую ветку в `main` и исправлять после. Отклонено: текущая ветка — незавершённый PR, а основная ветка должна оставаться нетронутой до приёмки.

## Критерии готовности

1. Все CI workflows для принятого кандидата успешно завершаются: unit tests, Windows build/smoke test, ASF plugin build.
2. Приложение запускается из исходников и собранного ZIP, создаёт локальную БД, корректно закрывается и сообщает понятную ошибку при недоступном ASF.
3. Обнаружение ASF, выбор конфигурации и ботов, запуск/остановка выбранных и всех ботов, импорт аккаунтов и управление прокси работают без утечки секретов.
4. Обновление инвентаря показывает активы выбранного бота; повторяющиеся/некорректные ID обрабатываются предсказуемо; резервирование не допускает конфликтов.
5. Заказ можно импортировать из разрешённого списка Playerok без дубликатов, проверить, сохранить и связать с конкретными активами.
6. Отправка невозможна без валидного заказа, актуальной проверки состава и явного подтверждения. Неизвестный результат блокирует автоматическую повторную отправку.
7. Данные и статусы остаются корректными после перезапуска приложения; сообщения об ошибках полезны, но не содержат паролей, токенов или trade URL-токенов.
8. Документация описывает установку, обновление, настройку ASF и ограничения; артефакты содержат актуальный build SHA и инструкции.
9. Перед объявлением готовности выполнен ручной приёмочный прогон с тестовым ASF/Steam-аккаунтом и низкорисковым тестовым заказом. Этот пункт невозможно подтвердить только CI.

## Дополнительные наблюдения от 2026-10-27

- README и .gitignore не содержат известных явных credentials в просмотренных фрагментах; полный поиск по всем файлам и Git history пока не завершён, поэтому безопасность публикации нельзя считать полностью подтверждённой.
- integrations/asf/proxy_config.py поддерживает разделители ;, |, запятую и TAB, но подсказка UI пока перечисляет только ;. Исправить рассогласование после добавления regression-теста.
- Proxy URI builder обрамляет IPv6-хост квадратными скобками, однако текущие тесты не закрепляют round-trip IPv6 и разбор URI.
- Context7 подтвердил важность корректной обработки keyring.errors.NoKeyringError и жизненного цикла QThread; это направления проверки, но само по себе не доказывает наличие ошибки в приложении.
